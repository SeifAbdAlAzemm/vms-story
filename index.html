05 · The baseline

Verification & Validation

Turning vague requirements into clear, testable ones

Worked exampleF-04Vehicle List, Search & FilterMust · Confirmed
Before verification

Browse and filter the vehicle list by attributes such as type, brand, status, and other key fields.

Issues found
  • “Search” is in the name, but no search fields are defined
  • “Other key fields” is vague, so it can't be tested
  • Several filters at once: AND or OR?
  • Browse undefined: paging, sorting, empty results
  • Archived vehicles and performance not addressed

+ 8 more points in the verification review

After verification Verification-ready

Authorized users can view, search and filter the vehicle list using defined search fields and attributes, with clear handling of empty results and large result sets.

  • SearchVehicle ID · Plate Number · VIN/Chassis · Model
  • FiltersType · Brand · Status
  • LogicMultiple filters use AND · search works with filters
  • BaselineEmpty state · Pagination · Sorting
  • Open points6 marked [CONFIRM] for the stakeholder
ValidationAre we solving the right need?Checked with the stakeholder
VerificationDid we write it the right way?Clear, specific and testable

07 · From requirement to backlog

User Stories & Exception Handling

VMS Project | Example: US-01 — Add Vehicle

User story · US-01

“As a Fleet Director, I want to add a new vehicle with its master data, so that every vehicle in the fleet is held in one central record.”

Trace: F-01 · BR-001 · BRL-13 · NFR-SEC-02
What I defined
  • Required inputs and data types
  • Acceptance criteria
  • Business rules and validation
  • Exception and error-handling scenarios
Acceptance criteria
  1. 1

    Given I have Create permission, When I open Add Vehicle, Then the form shows the required fields: Plate Number, VIN/Chassis, Model, Type, Brand.

  2. 2

    Given all required fields are valid, When I click Save, Then the vehicle is created as Active/Available with its Vehicle ID.

  3. 3

    Given the Plate Number already exists, When I click Save, Then a duplicate error appears and no record is created.

  4. 4

    Given a required field is empty or invalid, When I click Save, Then validation feedback is shown and no record is created.

Exception handling
ScenarioExpected system behavior
1Duplicate Plate Number or VIN/Chassis NumberInline duplicate error; no record is created
2Required field empty or only spacesField highlighted, “This field is required”, entered data kept
3Save clicked twice rapidlyOnly one vehicle record is created
4Network fails during Save“Connection error, please try again”; no partial record, retry allowed
5User lacks Create permissionAccess denied and the attempt is logged
